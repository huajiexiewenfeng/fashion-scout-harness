# Fashion Scout Harness：需求与架构 v0.2

日期：2026-10-06（Asia/Shanghai）；契约修订：v0.2-contract-2，附 2026-10-07 浏览器来源生命周期修订。本地实现的验证记录见 docs/verification；实站来源到导出及最终安装包仍待验收。本文取代 v0.1 的多页面后台、人工候选前置、强制版本确认及延后 Skill 方案；原有可靠性要求仍属于首版验收。

## 1. 产品目标与范围

减少找款、逐图保存和整理的人工操作。正常流程只有开始巡检、浏览、收藏、导出；使用默认方案，不每轮重新配置。

| 维度 | v0.2 决策 |
| --- | --- |
| 环境 | Windows 本机、单用户；Web 与 Worker 独立进程 |
| 入口 | 首版对话 Skill 与页面共用业务 API |
| 启动 | “开始巡检”是唯一新巡检意图；活动任务复用，默认手动，无定时器 |
| 查询 | “看看新款／结果”、打开页面、启动服务不创建巡检；显示最近执行事实 |
| 恢复 | 已收到的数据由 Worker 恢复；浏览器来源等待 Codex 前台后继续同一已接受 Run |
| 来源 | 首站 Futario New In；其他站点后续逐站验收 |
| 处理 | 符合规则商品自动下载支持范围内图集、校验归档、预览、分类和去重 |
| 分类 | 来源类别规则映射；人工修改优先；未识别类别不阻断采集 |
| 页面 | 新款／收藏、类别筛选、图集、收藏、一步导出；运维信息折叠 |
| 存储 | SQLite 加可配置本机素材目录；UTC 入库，Asia/Shanghai 默认展示 |
| 输出 | 收藏款全部已存图片 ZIP，每款一目录，信息／来源／缺失说明／总清单 |
| 后续 | 飞书、AI 分类、定时、多用户、跨机、相似款、目录迁移 |

临时指令生成任务快照，不写默认方案；修改默认方案是设置中的单独操作。无强制待分类、候选或人工版本确认流程。

## 2. 模块与进程

模块化单仓库，两个业务进程共享服务与模型；首版不引入 Redis、Celery、微服务或浏览器自动化依赖。

| 模块 | 职责与边界 |
| --- | --- |
| Skill | 识别明确意图，调用固定客户端；browser 模式用当前会话公开浏览器工具提交观察和选中图片，不改 DB |
| 启动器 | 复用／启动 Web 与 Worker，检查身份、就绪、端口、心跳；不创建巡检 |
| Web/API | 配置、持久任务创建／查询、商品状态、预览、导出申请；不在 HTTP 内跑完整采集 |
| Worker | 持久工作、租约／恢复、图片校验归档、核验、ZIP；已完整收到的工作不依赖对话存活；browser 来源采集依赖 Codex 前台 |
| Futario 适配器 | 分页、稳定 ID、字段／时间／图集解析、覆盖证据；不裁定总体成功 |
| 业务服务／SQLite | 幂等、短事务、素材版本、人工状态、任务与文件证据的权威 |

Web 就绪不等于 Worker 在线。执行器离线时已接受任务保持 queued，不假称正在采集。关机／休眠期间无法采集；恢复后确认旧执行者失效，再继续原任务。Windows 脱离父进程及休眠行为须实测，尚无已验证安装包。

## 3. 持久任务、覆盖与失败

Run → SiteRun → ProductItem → ImageItem。创建时冻结默认方案修订号、临时覆盖、入口／栏目、日期窗口、未知日期策略、扫描／空间上限、适配器版本。

2026-10-07 修订：用户接受“采集时保持 Codex 运行即可”。source_mode/adapter_version 与浏览器观察、选中图片、接收字节和前台时限在 Run 创建时冻结。原 HTTP Run 不转换来源，旧幂等键／意图／快照保持原含义。browser 等待前台时记 waiting_host/SOURCE_HOST_REQUIRED；等待不消耗 R1 实际处理时间，不重复领取，不阻断独立导出／维护。前台恢复用 browser-continue 继续同一 Run，新 epoch 使旧来源会话失效；客户端 resume 仅恢复不确定回执，两者不同。

所有“开始巡检”入口使用同一个 API。相同幂等键复用原响应；不同请求在已有 queued/running/interrupted/cancelling 巡检时也返回该任务，不另排巡检。临时参数未采用时返回实际快照和原因；并发判重由事务与唯一约束保障。

生命周期：queued → running → succeeded / partial / failed；取消经 cancelling → cancelled；失效租约记 interrupted，恢复同一 run_id。局部重试是原任务的新 Attempt，不是新巡检，也不重扫已完整发现范围。导出和文件核验为独立持久任务。

租约带 owner、epoch、heartbeat、截止时间；领取／接管用短事务 CAS，旧 epoch 不能提交业务状态。网络／文件 I/O 不占 DB 长事务。步骤可重入，已完成文件与人工状态不清空；新增数量按业务键去重。

| 结果 | 判定 |
| --- | --- |
| succeeded | 请求栏目范围有完整枚举证据；规则命中商品必需步骤及明示支持图集完成并校验；可以零商品 |
| partial | 有有效页面／商品／文件结果，但范围触顶、分页不稳、日期排除限制、详情失败或缺图等仍有未满足项 |
| failed | 无有效采集证据且执行失败，例如首请求全部拒绝；不能归为无新品 |
| cancelled | 保留已完成记录与当时覆盖；不视为成功扫描 |

仅完整扫描且无规则命中商品，才显示“本次规则范围内无新结果”。未知日期被配置排除，也必须记录 coverage_exclusions，按保守口径标 partial，不能显示无新品。

429／临时网络错误有限退避并尊重 Retry-After；认证、验证或结构变化标记需要处理，不绕过限制。单站／单图片失败不终止其他工作。空间不足停止新增下载，保留可恢复步骤。集中展示需要人工处理的原因；日志无凭据／私密请求头。

## 4. 来源日期与 Futario 证据

分别记录 source_published_at、source_created_at（均可空）、first_seen_at、observed_at；保留原字段、偏移及证据 URL。源站发布时间不证明款式首次上市或入栏时间；首次发现只说明本系统首次观察。栏目名称、图片版本参数、销售文案不能补造日期。

首次巡检建基线，优先自动归档源站标注近 14 天商品；未知日期按明确配置自动处理，不要求人工先选候选。后续归档新发现商品及已有商品的素材更新；先前因规则未入库的商品仍按本次规则重新判断。完整规则见[接口契约](implementation-plan.zh-CN.md#4-futario-适配契约与初始参数)。

2026-10-06 前期调查来自已确认开发基线，本轮未重新扫描整站：

| 小样本证据 | 不能据此宣称 |
| --- | --- |
| 公开 collection products.json（limit/page）、商品 .js、HTML 页 1／2／12 可读；当时 12 页，前两页各 20 项、末页 6 项 | 未全量去重，不能证明 226 款或全栏目覆盖 |
| 默认 Featured/manual；末页样本发布时间比首页首款晚 | 不能遇旧即停或只扫首页 |
| 60 款均单色；ID、published_at、类别、变体、图集可读 | 多色关系和变体独有图尚待验证 |
| 40 款 description 未见 img/video/iframe | 不证明全站没有动态详情图／视频 |
| 两款图集分别 6／4 张；两张源文件可解码，900×1200／1536×2048，约 2／4.3 MB | 不代表平均体积、全图集验证、最大分辨率或拍摄原片 |

来源示例：[棕色开衫](https://futario.com/products/refined-chocolate-brown-ribbed-asymmetric-button-knit-cardigan)、[紫色连衣裙](https://futario.com/products/plum-purple-floral-high-neck-dress-with-sheer-long-sleeves-and-ruffle-fishtail-hem)。销售描述不转成系统确认事实。

首版拟支持结构化 product.images 图集。变体图、内嵌／动态详情、视频分别记录 unknown／unsupported，未验收不提升为 supported。每个 manifest 保留实际范围；succeeded 只针对明示范围，不代表全站全媒体下载。

采集及导出均区分承诺范围与范围外能力说明。范围外 unknown／unsupported 不单独导致 partial，也不创建需人工处理的常驻告警；承诺图集的枚举不完整或缺图则必须标 partial。

浏览器观察只能声明 browser.gallery。完整 product.images、变体身份／关联、日期与原始分辨率未证实时保留 unknown；完整商品图集是原目标的一部分，因此即使页面可观察图片齐全，browser Run／v2 导出仍为 partial，不借缩小范围报 succeeded，也不覆盖既有 product.images 最新完整指针。6 张已枚举、5 张已存必有缺失。旧 v1 导出保持原字节／摘要规则；browser 或混合历史用 v2 按版本标范围，仍打包所有历史独有 SHA。

## 5. 素材版本与文件一致性

商品键为 site_id + source_product_id，跨站相似款不自动合并。URL 定位来源，SHA-256 判断内容；同 URL 可能更新，不能永久跳过检查。保存每轮 Observation 与有序图集关系；顺序、URL、内容变化保留历史，不覆盖旧证据。

“最新可用版本”是最近观察且至少一张经校验可读的版本；无可读图片则回退上一可用版本，提示最新观察未完成。partial 版本可成为最新可用，但必须标已存／应有与缺失项。最新完整版本另存供详情查看，无需人工确认切换。

默认图集先展示最新可用版本，历史可查看。收藏导出以最新可用版本顺序与信息为主，**再附该商品历史版本中的独有已存图片**，同哈希只放一次，清单列全部版本／来源关系。“全部已存图片”不能缩成“最新版本图片”。损坏／丢失文件记缺失，不伪装已导出。选择、版本、文件集合在导出创建时冻结，后续收藏或巡检不改变该包。

同时冻结每款 promised_coverage／required_coverage、该范围的枚举证据及应有图片关系。导出完整性只依据这份承诺：图集全齐、视频在范围外未支持 → succeeded（范围内成功），能力说明仍在 manifest；已发现图集 6 张但只存 5 张 → partial，缺失 1 张可查。承诺范围内枚举不完整、损坏文件或冻结资产缺失也为 partial；不能因视频未知让正确图集包永久告警，也不能缩小承诺范围掩盖缺图。

归档：同卷临时下载 → 格式／实际解码／像素／哈希校验 → 唯一不可变目标 → DB 关系提交。保留 staging journal，恢复核对孤立文件、缺失关系、临时残留。文件与 DB 无共同事务，不承诺断电绝对原子，核对失败不静默完成。

配置 data_root、media_root；数据库记 storage_root_id 与相对路径。文件名用安全 ID／哈希，处理 Windows 保留名、长度与大小写碰撞；访问须确认解析后仍在根目录内。改根目录只影响后续写入，历史根继续可读；迁移后续独立设计。

取消收藏、排除、源站下架均不删正式素材。可重建预览缓存可限额淘汰。按需核验存在／大小／哈希，记录核验时间，缺失支持补抓。DB 一致性备份加独立素材备份并验证恢复；同盘备份不代表防磁盘损坏。首版不支持网络盘。

## 6. 页面、分类与统计

首页“新款／收藏”两视图及少量类别筛选。默认新款流包含曾命中归档规则且未被人工排除的发现商品，不以图片完成为可见门槛；下载中、全图失败或详情失败均可用占位和状态显示。只保存元数据、从未命中规则的历史项留在任务明细，不挤入默认流；已看商品仍保留在列表后组与收藏中。

默认未看优先；两组内按 first_seen_at 降序、product_id 升序稳定排序。打开图集且实际呈现至少一张图片才记 viewed_at，列表曝光／预加载／仅错误占位不算已看。浏览写入不改变当前翻页会话的集合与分组；刷新才应用新的已看状态。分页快照过期则明确要求刷新，不接着用变动后的排序漏项或重复。

已看按商品保留，不因普通 Observation、顺序变化或下载重试重置。实际可用图片内容集合变化时显示“素材有更新”，不自动重新推入未看组；seen_version_id 与 seen_content_digest 记录上次实际呈现版本用于说明更新，查看历史版本也不清空已看。收藏、排除、人工类别独立字段；规则更新不覆盖人工类别，清除 override 才恢复规则类别。

“开始巡检”与 Skill 同义；状态区简要呈现最近巡检、正在执行／恢复与待处理汇总。技术日志、分页、站点、存储、重试／取消／核验放设置或详情。来源分类是规则映射，不是 AI 推断服装事实。

首次发现与源站近期可能重叠，不能直接相加。商品、图片关系、物理文件、复用／补回、尝试次数分别统计。发现未完成只显示已处理／已发现；采集、人工状态、导出状态相互独立。

首个可运行切片不等于全项通过。以下均需实际证据：

| 编号 | 场景与判定 |
