## P0：开发准备

固定首版范围与接口，读取实际仓库版本、保留前期 Futario 小样本证据边界。交付为 README、[架构 v0.2](architecture.zh-CN.md)、[实施与接口契约](implementation-plan.zh-CN.md)及本路线图。

出口：四份文档对入口、默认手动、候选非必需、素材自动归档、版本保留、全部已存图片导出无矛盾；依赖单一推荐、Windows 环境门槛与待验证参数明确。文档评审通过不表示适配完成。

## P1a：首个可运行纵向切片

Skill 是本阶段入口，不延后。按保存默认方案串起：

1. 本机启动器启动／复用独立 Web 与 Worker，不创建巡检。
2. “看看新款”只读已有结果；“开始巡检”持久化任务，重复／运行中复用。
3. Worker 从 Futario 小范围发现，按规则自动下载支持图集、校验归档与来源分类。
4. 页面新款／收藏、图集预览、真实浏览及未看优先；下载失败款仍可见，翻页冻结分组，刷新才应用已看排序；无需人工候选或版本确认。
5. 收藏款全部已存图片 ZIP，每款目录、来源／信息／缺失说明／总清单；按承诺范围判完整，范围外未支持媒体仅作能力说明。
6. 关闭页面／对话继续；一次中断恢复与重复运行证明已完成文件和人工状态保留。

小范围扫描触顶必须 partial；不据此宣称全栏目无新品。出口是这条链路有实测证据，仍不是首版全部可靠性验收。

## P1b：按契约补全可靠性与覆盖

[实施契约的文件归属](implementation-plan.zh-CN.md#6-实现顺序文件归属与依赖)区分编码与集成前置：T1 公共 DTO／迁移接口验收后，T2／T3 可按接口编码；T4 还需已验收的 T3 路由契约，T5 还需已验收的 T2 归档契约，才能各自使用夹具并行编码。T4 真实集成等待 T1 启动器与 T3 路由实际产物验收，T5 真实集成等待 T1 数据层与 T2 归档实际产物验收；缺前置时保持等待，Mock 通过不代表整链路可用。T6 在 T1–T5 产物接入后执行集成验收。公共表／DTO 单一所有者不变，并行需 Manager 正式派发。

补齐分页终止／重排／上限、未知日期、多色与动态详情边界、来源同 URL 更新、部分失败、取消／重试、租约 fencing、staging 故障恢复、空间预算、文件核验、备份恢复、本机访问保护。只支持经证据确认范围，未验证能力继续标 unknown。

出口：逐项完成[架构 A01–A12](architecture.zh-CN.md#7-第一版全部验收门槛)，保留真实命令、输入／输出、版本和失败案例；合成故障与真实来源验证分列，不以夹具通过证明源站适配。

## P1c：首版整体试用与验收

完整栏目在预算内的遍历与稳定性需实测；合理扫描上限、并发、磁盘预算在数据足够后锁定。页面保持新款／收藏主流程，任务、日志、存储、站点放设置或详情。

完成 A13 可用性与耗时观察；人工和系统都计纠错、下载、整理、导出。减少约三分之一是目标，不提前承诺。Windows 关闭终端／对话、重启、休眠、磁盘失败等现场门槛未过则不得宣布首版交付。验收通过后才补真实安装／运行说明。

## P2：基于反馈扩展

后续另行确定范围：更多站点、飞书、AI 分类建议、可配置定时、相似款检索、目录迁移、多用户及跨机部署。默认仍手动；启用服务不意味着授权定时采集。不得把这些扩展加入首版日常操作门槛。

文档完成、实现完成、真实站点验证和独立验收分别记录。每个切片可以逐步完成，但不降低首版 A01–A13 的最终要求。
