### 来源与规则

- 固定栏目 https://futario.com/collections/new-in，固定结构化适配版本 futario-json-v1。只读公开 collection products.json 与 products/handle.js；字段结构改变明确失败，不启浏览器、不执行描述内容。
- 分页签名、ID 去重、页重复/交叠保护、有界页/商品/请求上限。不按日期早停；两遍均达到短页/空页结束、ID 集合一致且无错误才 discovery_complete。排序变化而集合稳定允许完整；并不承诺源站原子快照。
- raw_published_at、raw_created_at、解析后 UTC 时间、date_reason 与本地 first_seen 分开。缺失、无时区、无法解析、未来日期为 unknown。首次基线按时间窗口及 unknown 策略；完整基线后新发现（即使日期旧）归档，已归档商品重新校验；旧的未归档项继续按日期规则。
- Run 创建事务写 run_seen_products；collection_products 固定 seen_before_run/eligible/rule。重试不能因本轮先前已插入 Product 而改变新发现判定。partial 不建立完整发现基线。
- 命中先写 first_eligible_at、资格证据及原始类别/规则类别。详情或图片全失败仍可读取商品标题与状态；人工类别优先，收藏、已看和历史不重置。请求失败只记错误，不删除商品/素材。

### 网络与资源

HTTPX 自定义同步 transport 接 httpcore 的固定地址 backend：每次连接解析、检查全部返回 IP 必须公网，连接精确数字 sockaddr，核对 peer；HTTPS 保留原 Host/SNI 与证书验证，不进行第二次主机名解析。无环境代理、自动重定向、TLS 关闭或私网例外。每跳显式验证来源域/端口/协议，最多4跳，拒绝 HTTPS 降级。

业务 JSON 只向 futario.com；图集只接受 Futario 自域或官方 Shopify 接口示例使用的 cdn.shopify.com，图片必须由来源 JSON 明确提供。当前实站请求未获得响应商品，因此没有新的 Futario CDN/图库实测确认。不能将通用 Shopify 文档当作 Futario 全站适配证明。

network.resolver_mode 冻结在 Run：system 为默认；google_doh 为本任务明确允许的固定提供者配置。后者以认证 HTTPS 连接固定 Google 引导地址8.8.8.8、Host/SNI=dns.google，查询官方 JSON API；校验状态、问题名/类型、CNAME关系、记录名/类型/TTL、公网地址及响应上限。不接受源站提供者 URL，不缓存临时业务 IP，不改系统 DNS/hosts。提供者故障失败关闭。DNS 等待有界，后台守护解析线程不能在调用方超时后继续发起业务连接。

连接/读/写/池与整个 fetch 均有限超时；请求最多3次，5xx/429及网络故障有界退避，Retry-After 优先，超过请求等待预算返回 RETRY_DEFERRED。006 保存来源 not-before；同 Run 重试、新 Run、重启不能跳过冷却，冷却拒绝不扣请求预算。响应原状态/Retry-After/peer/接收时间保存于005/006表。合法秒数或 HTTP-date 按服务器指示推导；缺失/无效头使用明确标为 local_policy 的有界本地策略，不伪称服务端截止时间。旧响应缺失时可保留 not_before=NULL 的未知等待限制，不能猜期限。

当前采集器串行执行详情和图片，每类实际并发均为1，低于配置上限；不宣称实现双图片并发。站点共用限速和退避。max_http_requests/max_image_requests 和字节/详情/发现预算按 Run 持久累计，retry 不清零。run_total_seconds 为每次取得租约后执行段的 monotonic 时间上限，包含本次运行中的请求/解码/有界短退避，不含两次执行间的停机/外部冷却等待；collection_runs.started_at 仅保留首次执行审计时间。耗尽累计预算的 issue 明确 retryable=false，提示复核冻结限额后显式新建 Run，同 Run 不能重置限额。下载预算保守计入 JSON 与图片响应体；每次请求先预留最大响应体加64KiB流块，预算不足提前停止，可能低于用户上限结束。单图有字节与像素上限；data/media 两卷检查空闲保底及暂存预留。文件权限错误不作为网络重试。

### 图片、版本与恢复

Pillow verify 后重开 load，检查实际 JPEG/PNG/WEBP/GIF 格式、尺寸、像素、动画限制与字节/hash；HTTP200不等于成功。不转换或补造图片。每轮对支持图集重新 GET，因此同 URL 内容变更可发现；同内容跨 URL/图序变更不创建新的内容版本标识，但保留新的有序 manifest revision。

T1 Archive 负责 journal/epoch/generation/不可覆盖发布，T2 在 stage 前完成图片验证。资产按内容 hash 路径复用，商品版本与图片/variant 关系另存；历史版本不删。latest_observed、latest_available、latest_complete 分开维护，最新缺图不能抹掉旧可用图，也不能省略最新 missing_ids。

材料 content_digest 仅按有效图片去重 SHA256 集合生成，不含缺图数、顺序、URL或source ID；覆盖变化存入 manifest revision。007 owned_temps 记录每次暂存的 Run/item/epoch/文件身份。成功提交资产后清理独立重复副本，失败未stage的自建文件也清理；清理持有有效租约和写锁，检查路径、身份和活动journal引用。旧epoch无删除权，正式原件和其它Run不清理。崩溃后的未完成journal保留字节供恢复，commit后残留在下一次该Run恢复时清理。身份不明/变化或权限错误明确保留待查，不猜测删除，详见v2记录。

Worker 的 retryable journal 交由真实 Collector 用同 Run/item 重取、验证、stage、commit；已完成项重新核验本地文件后复用。blocked 项保留错误并继续其他项；根目录/权限等系统错误停止该阶段。范围外视频/描述媒体只作能力说明；支持图集6张存5张为 partial，零有效图片且不完整为 failed。发现完整、没有规则命中项可明确 succeeded 空结果；不完整发现的空集合不会冒充无新款。
